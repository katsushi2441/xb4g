# Kurage 国会トラッカー — テーマごとに、国会でだれが質問し、政府が何と答えたか

決めたテーマ（例：内密出産、OTC類似薬、不登校）について、**全国の国会議員の質疑と政府の答弁**を
国立国会図書館の国会会議録検索システムから集め、日付順に並べます。
要約も論評もしません。出すのは、テーマの語を含む文の抜粋と、会議録へのリンクだけです。

実際に動いているもの: <https://xb4g.com/giin/tracker>（約90テーマ・質疑3万件超）

---

## 何ができるか

- **テーマのページ**（`/tracker/<key>`）
  - 数字で見る要点（質疑・答弁の件数、取り上げた議員の数、最初と最新の日付）
  - いま政府は何と答えているか（大臣・副大臣・政務官・政府参考人の直近の答弁）
  - 直近の質疑、年ごとの件数、党ごとの件数、よく取り上げた議員
  - 発言のあゆみ（全部／質疑／答弁／参考人で切り替え、新しい順）
  - よくある質問（会議録のデータから機械的に作る。構造化データ FAQPage つき）
- **質疑1件のページとカード画像**（`/tracker/<key>/<発言ID>`）
  - 質問とその直後の政府の答弁を、1枚の画像（1200×630）にします。ページのURLを X や Slack に貼ると、このカードが表示されます
  - 「タイトルとURLをコピー」「Xで共有」のボタンつき
  - 答弁は「質問の直後の政府側の発言」を機械的に取り出したものです。質問が途中で別の論点へ移り、
    直後の答弁がその別の論点への答えのときは、組にしません（答弁にもテーマの語があるか、
    質問の後ろ3割でテーマの語にふれているときだけ組にします）
- **テーマの一覧**（`/tracker`）— 名前や語で絞り込めます
- **sitemap.xml**（`/sitemap.xml`）

## 入っているもの

```
index.php                 画面のルーター
lib/                      db / text / ui / trackers / tracker_pages / qa（質疑カード）
fonts/                    カード画像の日本語フォント（Noto Sans CJK を JIS第1・第2水準に絞ったもの。SIL OFL）
scripts/
  fetch_tracker.py        会議録からテーマごとの発言を取り込む（増分）
  classify.py             発言の立場（質疑／答弁／議事整理）を分ける規則
  ndl.py                  国会会議録APIの呼び出し（1回ごとに3秒待つ）
  make_ogp_trackers.py    テーマごとのOGP画像（make_ogp_all.py の部品を使う）
  make_card_fonts.py      fonts/ を作り直す（ふつうは不要）
  tracker_jobs.py         毎日の更新（取り込み→OGP→サーバーへ送る→公開ページで件数を確かめる）
data/trackers.json        テーマの定義（見本3つ）
tracker_config.php.example
```

## 動く場所

- 画面: **PHP 8 と SQLite** だけ。常駐プロセスもデータベースサーバーも要りません。
  カード画像は PHP の GD（FreeType つき）で描きます。heteml・さくら・エックスサーバーなどで動きます。
- 取り込み: **Python 3**（標準ライブラリのみ）。OGP画像を作るときだけ Pillow を使います。
- **LLMを使いません。** 立場の分類も抜粋も、決めた規則による機械的な処理です。運用にAPI費用はかかりません。

## 設置

```bash
# 1. テーマを決める（data/trackers.json。下の「テーマの足し方」）
# 2. 会議録から取り込む（初回はテーマごとに数分。国会会議録APIは利用登録不要）
python3 scripts/fetch_tracker.py
# 3. OGP画像
TRACKER_PUBLIC_URL=https://example.com/kokkai/ python3 scripts/make_ogp_trackers.py
# 4. 設定を置く
cp tracker_config.php.example tracker_config.php   # G_BASE / G_HOST を置き場所に合わせる
# 5. 一式をサーバーへ置く（data/ と fonts/ は .htaccess で Web から読めないようにしてある）
```

`.htaccess` の `RewriteBase` も置いた場所に合わせてください。
カード画像は最初に開かれたときに描き、`data/cache/qa/` に置いて2回目から使います（このフォルダに書き込めること）。

## テーマの足し方（`data/trackers.json`）

```json
{
  "key": "naimitsu-shussan",
  "name": "内密出産の法整備",
  "short": "内密出産",
  "words": ["内密出産", "こうのとりのゆりかご", "赤ちゃんポスト"],
  "from": "2016-01-01",
  "lead": "ページの冒頭の説明",
  "questions": ["論点1", "論点2"],
  "seo_word": "内密出産",
  "seo_title": "検索結果に出す題名（32字以内）"
}
```

- `words` のどれかを含む発言を集めます。語に空白を入れると「全部を含む」（AND）になります（例 `"後期高齢者 二割"`）
- `from` より前の会議録は取りに行きません。古くするほど初回の取り込みに時間がかかります
- 語や `from` を変えたテーマは、次の取り込みで全部取り直します。それ以外は、最後の日付の45日前から取り直します
  （会議録は会議から1〜2週間おくれて公開され、あとから足されることもあるため）
- `notice`（相談窓口の案内）と `links`（制度の公式ページ）も書けます。`notice` があるテーマは、数字より先に案内を出します

## 毎日の更新

```bash
python3 scripts/tracker_jobs.py
```

`.tracker_env`（または環境変数）に `TRACKER_PUBLIC_URL`・`TRACKER_REMOTE_DIR`・`FTP_HOST`/`FTP_USER`/`FTP_PASS` を書くと、
SQLite と画像をサーバーへ送り、公開ページの件数が手元と一致したときだけ成功とします。
同じ機械に置いている場合は `TRACKER_REMOTE_DIR` を空にしてください。cron でも rqdb4ai でも呼べます。
テーマが多いと取り込みに時間がかかります（約90テーマの増分で約20分。会議録APIへの配慮で1回ごとに3秒待つため）。

## 件数の数え方

発言の冒頭の話者表記から、**議員の質疑・政府の答弁・委員長の議事整理・参考人**に機械的に分けます。
分けずに数えると、委員長や大臣を務めた議員の件数が跳ね上がり、「よく質問している人」に見えてしまいます。
「取り上げた議員」に数えるのは質疑だけです。参考人・公述人・証人は議員ではないので別に数えます。

## 出典と、守っていること

- 発言・会議名・日付: 国立国会図書館 国会会議録検索システム（利用登録不要）
- 会議録の本文は要約しません。語を含む文をそのまま抜き、全文は会議録へのリンクで読んでもらいます

## このシステムがしないこと

- 要約しない（機械的な抜粋だけ）
- 論評しない
- 賛成・反対を判定しない
- 議員に順位をつけない（件数の差は、熱心さの差でも正しさの差でもありません）

## 議員発言ログとの関係

「特定の都道府県の議員が、国会でいつ何を質問したか」を議員ごとに引くのは、別の商品（Kurage 議員発言ログ）です。
こちらは議員の名簿を持たず、テーマの語だけで全国の発言を集めます。
